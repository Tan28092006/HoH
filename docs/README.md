# Documentation map

Read the row whose trigger matches your task; do not read this folder end to end.
**Status** says how far to trust a document: *current* documents are kept in step
with the code; *snapshot* documents describe the system at the date they name and
are not updated afterwards. When a snapshot and the code disagree, the code and
its tests win.

## Where else knowledge lives

- **Role behavior for agents** lives in `skills/<role>/SKILL.md` (short control
  cards) and their `references/`. These ship inside the wheel and are installed
  into clients; change them as product code, with `tests/test_skill_*.py`.
- **Client launch configs and prompts** live in `deploy/`.
- **Live ticket state** lives in the control plane database. Never cache it in a
  document; ask `work.discover` and resolve the current packet.
- **Decision records written by the service** go to `docs/decisions/` in the
  managed project (see `semantic_record.py`), not in this folder.
