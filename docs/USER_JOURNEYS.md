# MVP user journeys

## Planner

As a Planner, I want to create a feature hierarchy and executable tickets with observable acceptance criteria, so that Developer and QA agents receive bounded work.

## Developer

As a Developer, I want to discover ready tickets for my role, resolve their context, claim one with a lease, report progress, and submit an immutable candidate, so that another Developer cannot overwrite my work and QA tests the correct artifact.

## QA

As a QA agent, I want to discover frozen candidates, attach evidence to acceptance criteria, and submit an independent verdict, so that failures become explicit rework context rather than disappearing in chat history.

## Human operator

As a human operator, I want a live project board showing features, tickets, leases, candidates, evidence, and agent activity, so that I can understand and intervene in the workflow without reading agent transcripts.

## Security boundary

As a project owner, I want the backend to enforce role permissions, project scope, ticket state, candidate identity, and optimistic concurrency, so that local skill instructions are guidance rather than the only protection.
